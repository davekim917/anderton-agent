# jq 1.8.2 in the agent image

The image installed Debian bookworm's `jq` package, which is 1.6. The container skill scripts are written and
tested against the host's jq 1.7, so programs using 1.7 syntax (an `if` with no `else`) failed to compile inside
agent containers and `codex-review.sh merge-check` could not run there. The image now installs the upstream
1.8.2 release binary instead: the latest stable release, and the first upstream build carrying the security fixes
released after 1.7.1.

The host runs Ubuntu's jq 1.7.1, which has 9 of those security fixes backported (not CVE-2025-49014 or ten of the 2026 ones), and `codex-review.sh` and the other scripts
run there too. They stay within what jq 1.7 and 1.8 share: a 1.8-only builtin (`trim`, `add/1`, `skip/2`,
`toboolean`, `@urid`) works in a container and breaks on the host. The script suites run under the host's 1.7,
which catches that.

## docker:jq none → 1.8.2

Source: https://github.com/jqlang/jq/blob/jq-1.8.2/NEWS.md (1.7, 1.7.1, 1.8.0, 1.8.1 and 1.8.2 sections, read against the 1.6 package it replaces)

- the binary installs only when its bytes match the digest pinned from the release's `sha256sum.txt`, and the build fails unless it reports `jq-1.8.2` · not covered: an image build property, checked by `sha256sum -c` and the version comparison in the Dockerfile itself
- an image jq older than the jq the container scripts are tested under fails the suite · test: container/jq-version.test.ts
- a later release bump reads both arch digests from the release's `sha256sum.txt` · test: src/container-updates.test.ts
- 1.7: `if … then … end` without `else` compiles (identity else-branch), along with `$binding` object keys, `.a.["b"]` and `.a.[]`; codex-review.sh already uses the first, and its suite fails to compile under 1.6 and passes under 1.8.2 · test: scripts/codex-review.test.ts
- 1.7: number literals keep their precision through passthrough and comparison, and 1.8 also keeps it through negation, `abs` and `length` · not covered: the container scripts order GitHub database ids as strings (`receipt-order.jq`), never as numbers
- 1.7: `--exit-code` exits 1 on a last output of `false`/`null` and 4 on no output; `halt`/`halt_error` exit at once; `try`/`catch` no longer catches errors raised after its body; `error(null)` throws `null`; codex-review.sh uses `-e` and `halt_error` and its suite passes under 1.8.2 · test: scripts/codex-review.test.ts
- 1.7 and 1.8: `sub`/`gsub`, empty regex matches, non-matched optional capture groups, `nth/2` and string multiplication by 0 are fixed, `U+001F` is rejected in string literals, and the precedence of binding syntax against unary and binary operators changes; the container scripts' suites pass under 1.8.2 · test: container/skill-shell-tests.test.ts
- 1.8: `index`, `rindex` and `indices` on strings count code points rather than bytes; smoke-build-identity.sh slices a route source at an `index` result and compares it with the API base, which gives the same answer on both versions while the base is ASCII; its base check was locale-dependent (en_US.UTF-8's `[A-Za-z]` admits `ä`), so it now validates in the C locale and refuses a non-ASCII base everywhere (case R31 of smoke-build-identity.test.sh) · test: container/skill-shell-tests.test.ts
- 1.8: `ltrimstr`/`rtrimstr` error on non-string input, `limit` errors on a negative count, `last(empty)` yields nothing, `tonumber` rejects surrounding whitespace, `--indent 0` no longer implies compact output, and `pow10` and `_nwise` are removed · not covered: every container script use of these passes a string or digit-only input, and none uses the rest (grep)
- 1.8: `strftime("%Z")` reports the zone name from timezone data (`GMT` where 1.7 printed `UTC`) · not covered: the container scripts format times only as `%Y-%m-%dT%H:%M:%SZ`
- 1.7: `--argfile`, `leaf_paths`, `recurse_down` and `scalars_or_empty` are removed · not covered: nothing under container/ uses them (grep)
- new builtins (`pick`, `debug(msg)`, `scan($re; $flags)`, `abs`, `trim`, `ltrim`, `rtrim`, `trimstr`, `add/1`, `skip/2`, `toboolean`, `@urid`), the `--raw-output0` and `--library-path` flags and `NO_COLOR` appear · not covered: additive, and a script using a 1.8-only one fails its suite under the host's 1.7
- security: 1.7.1 fixes CVE-2023-50246 and CVE-2023-50268; 1.8.0 to 1.8.2 fix CVE-2024-23337, CVE-2024-53427, CVE-2025-48060, CVE-2025-49014 and sixteen 2026 CVEs (heap overflows, use-after-free, unbounded recursion, hash-collision DoS) · not covered: fixes inside jq with no fleet-visible contract
